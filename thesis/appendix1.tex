\chapter{Prompt extracts}
\label{app:prompts}

The full prompts are in \texttt{src/prompts/} in the accompanying repository. Three
extracts are reproduced here because they carry the design arguments made in
Chapter~\ref{ch:methodology}.

\section{Court agent, Step 1 gate (shared by V3 and V4)}

\begin{lstlisting}
Step 1: First determine whether the scenario contains an OBJECTIVELY
COMPUTABLE fact -- meaning the scenario explicitly states BOTH (a) a formula,
percentages, or weightings, AND (b) every specific numeric input value that
formula needs (e.g. BOTH bidders' actual sub-scores). A formula or weighting
stated ALONE, without the specific input values to run it, is NOT objectively
computable -- treat that as Step 2B, not Step 2A. A stated correction, delta,
or adjustment (e.g. "the court reduced the winning bidder's marks by 40")
describes an OUTCOME, not an INPUT -- it tells you what changed, not the
original figures the formula was applied to, and does not by itself make the
scenario computable.
\end{lstlisting}

\section{Court agent, the hedged-fabrication ban}

\begin{lstlisting}
IF A FORMULA EXISTS BUT THE INPUTS ARE INCOMPLETE: do not invent, assume,
estimate, or hypothesise the missing input values to "complete" the
calculation, not even as an illustrative example, and not even if you
explicitly label it as an assumption (e.g. starting a sentence with "let's
assume the original scores were..."). Writing down a number that is not
stated in the scenario is fabricated evidence regardless of how it is framed
or hedged.
\end{lstlisting}

\section{Extraction agent, the symmetric instruction}

The extraction prompt states the anti-fabrication rule and then states its
converse with equal force, because losing a real formula through
over-summarisation silently downgrades every downstream assessment from exact
verification to qualitative review:

\begin{lstlisting}
EQUALLY CRITICAL -- DO NOT DROP REAL NUMBERS EITHER (read this as carefully
as the anti-fabrication instruction above; it is the same discipline in the
opposite direction): If the source text DOES state an exact scoring formula,
weighting, or specific figures ... you MUST carry that formula and those
exact figures into the description VERBATIM, not summarised into general
prose.
\end{lstlisting}

\chapter{Reproducing the results}
\label{app:repro}

\section{Environment}

Python 3.13, Ollama serving \texttt{llama3.1} (8B). Inference runs against local
Ollama by default, or against a tunnelled NVIDIA A10G on the University's Ronin
service by pointing \texttt{OLLAMA\_HOST} at the forwarded port. On Windows,
\texttt{PYTHONIOENCODING=utf-8} must be set for any redirected or backgrounded
run, because the case texts contain characters the default console codepage
cannot encode.

\section{Two reproducibility properties worth noting}

Extracted scenarios are cached to \texttt{batch\_results/\_scenarios/<slug>.json}
and the cache is load-bearing rather than an optimisation. Extraction is itself a
model call, so re-extracting per experimental arm would make the V3/V4 comparison
run two prompts against two different scenarios, confounding the single variable
the ablation isolates.

Batch summaries are rewritten after every run and carry a \texttt{complete} flag.
A batch marked incomplete is a crash-recovery artefact, not a result, and the
analytics interface renders a prominent warning over any such batch so that a
half-finished run cannot be read as a finished one.

\chapter{Ethics}
\label{app:ethics}

This project was assessed under the MSc Data Science Extended Research Project
ethics review process and recorded as requiring no further ethical review. No
human participants were involved and no personal data was processed. All case
material is drawn from published judgments in the public domain. The four Fusion21
documents that inform the agent designs are commercially confidential and are
summarised rather than reproduced; this is one of the reasons the system runs on
a self-hosted model rather than sending content to a third-party API. The two
operational documents supplied by a Fusion21 employee during testing were run
locally and are not reproduced here.
